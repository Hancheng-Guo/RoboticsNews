# 周报网页与 PDF 呈现规范

本文件约束**公开成品**的结构、文字层级和可执行的内容检查；[采编规范](EDITORIAL_GUIDE.md)决定收什么、如何核验，[维护手册](WEEKLY_OPERATIONS.md)决定如何入库与发布，[周报模板](ISSUE_TEMPLATE.md)提供逐期可复用的内容骨架。网页由 `scripts/build-site.mjs` 生成，PDF 由 `scripts/build-pdf.py` 从同一份 `site/current.json` 生成。变更模板时应同步检查两种输出，避免文档和代码分叉。视觉审阅可在条件允许时进行，但不是发布门槛。

## 1. 不可变的发布约束

1. 网站只展示**当前一刊或预告**：正式刊写入 `site/index.html` 与 `site/current.json`，预告仅写首页并删除 `site/current.json`。根目录 `diarys/YYYY-MM-DD.pdf` 每期留档，不能放进 `docs/`。
2. 刊期是北京时间周一，统计窗口是前一周周一 00:00（含）至本周一 00:00（不含），页面可写成“上周一至周日”。不要把预告或未结束的一周写成已出版周报。
3. 网页顶部、主标题之前必须出现清楚可见的 **`AI生成`** 标识；PDF 首页标题附近也应说明 AI 参与生成。该标识在桌面和窄屏下都可见，不依赖悬停或展开。
4. 网页和 PDF **不展示编辑说明、内部核查记录、`claim_evidence_notes`**。公开 `site/current.json` 也不应带内部核查记录。请留意：若把原始条目 JSON 提交到公开仓库，其中的内部内容仍会公开。
5. 每篇论文都展示**来源可确认的作者姓名（标出第一作者及有依据的通讯作者）→ 第一作者和通讯作者的单位 → 获许可的摘要原文及必要译文，或明确标记的转述**。通讯作者未被明确标记时显示“论文未注明通讯作者”。所有论文栏目，包括“论文速览”，执行同一规则。作者可按来源使用全名或缩写；不展示全文贡献总结。
6. 非论文条目保留中英双语摘要；证据标签与标题中的措辞必须一致。企业单方消息的“机构宣称，未独立验证”要在标题附近可见。
7. 发布前检查网页和 PDF 的内容、日期、来源及 PDF 目标路径。视觉改版不得改变统计口径和证据含义。
8. **每个公开条目只有一条可点击的来源链接**，取 `primary_url`；转载时标明“转载来源”。不展示摘要原文、第一作者/通讯作者单位、许可、代码、数据或其他辅助核查链接。刊期 PDF 与历史 PDF 的页面导航链接保留。依据 URL 仍保存在数据中，采编核验不因页面简化而省略。

## 2. 当前网页信息结构

从上到下排列：

1. 品牌导航：`RoboticsNews` 与“机器人学研究进展周报”。
2. 横向 AI 告知条：醒目的 `AI生成` 标签和“内容由 AI 辅助整理与总结；请以每条所列来源为准。”
3. 刊期首屏：`WEEKLY BRIEF · YYYY-MM-DD`、中文主标题、英文副标题、北京时间刊期、收录条目数、本期 PDF 链接。
4. 统计窗口说明：上周一 00:00 至周日 24:00 首次公开的信息；说明企业/机构单方内容的证据状态。
5. 有内容的栏目，依序为“学术研究 → 工业与应用 → 生态动态 → 论文速览 → 补录与更正 → 其他进展”。空栏目不显示。栏目内重点条目在前，再按四项评分之和降序、`importance_rank` 升序，最后才按 ID 稳定排序。
6. 页脚：站点名称与每周一更新说明。

`placement` 控制栏目，`category` 控制论文/非论文条目形式；二者不能互相代替。正式发布前尽量把 `unassigned` 处理成明确栏目。首页只显示本刊，不在页面混排历史刊。旧 PDF 留在 `diarys/`，当前首页 PDF 链接只指本刊。

已发布刊期修订时，在统计窗口后显示修订日期、具体变化及上一版 PDF 链接；PDF 首页展示同样的修订说明和归档链接。修订信息从该期元数据读取，内部核查记录仍不公开。

### 2.1 论文条目

每张论文卡片按下列顺序：证据标签（转载时另加来源标签）、最多三个主题标签、日期、中文标题、英文标题、**“作者”**及按来源顺序列出的姓名（标出第一作者及已确认的通讯作者）、**“第一作者单位”**、**“通讯作者单位”**、获许可的摘要原文及必要译文，或**“论文内容转述 / Paraphrase”**与中英转述、可选意义/局限、**一条来源链接**。通讯作者逐位显示；未被明确标记时写“论文未注明通讯作者”。摘要与单位的依据 URL 仍记录在结构化数据中，卡片不展示这些链接。

第一作者单位已核实时可有多个，按署名顺序列出；每项只写“单位名，国家或地区”。无法确认则显示“不明确”，不把其他作者或合作机构的单位混入。可转载的原文摘要从所引版本复制到 `abstract_original`；`abstract_zh_translation` 是忠实中文翻译。不能转载时这两个公开字段留空，使用有来源依据的中英转述。论文速览的核验底线相同，不因栏目缩短而猜测缺失信息。
通讯作者只能根据论文署名页、脚注或官方项目页的明确标记确认，不能由末位作者、邮箱或现职推断；每个通讯作者的署名单位与来源 URL 分别记录。

### 2.2 非论文条目

证据标签、最多三个主题标签、日期、中文标题、英文标题、中文摘要、英文摘要、可选意义/局限、一条原始来源链接；代码和数据 URL 只在数据中保留，不作为附加链接展示。`official_claim` 应显示“机构宣称，未独立验证”。标题不得把公司预期或剪辑演示写成已经证实的规模部署。

### 2.3 预告与空状态

预告展示下一期周一 08:00、预定统计范围、“周报正在编制中”和 `AI生成`；**不显示假条目、正式刊条数或不存在的 PDF 链接**。没有已发布内容的空状态只是构建兜底，不应被当作完成的正式周报发布。

## 3. 当前网页视觉基线

| 项目 | 当前值或做法 | 改版约束 |
| --- | --- | --- |
| 内容宽度 | `.shell` 最大约 940 px，左右留白 | 窄屏不能水平滚动或截断长英文术语/URL |
| 主色 | 深蓝 `#18263a`，青蓝 `#16738a`，浅底 `#f7fafb` | 文本和链接保持足够清晰的对比，不靠颜色单独传达证据状态 |
| AI 告知 | 浅黄色横条、深色标签，位于导航下方 | 必须先于主标题和正文，可在移动端换行但不隐藏 |
| 首屏标题 | 大字中文标题，英文副标题与刊期元信息 | 保留中英标题层级；日期和 PDF 入口可直接找到 |
| 栏目与卡片 | 栏目标题左侧色条；白底边框卡片 | 一条一张卡，来源链接与正文分开，便于扫描 |
| 重点标记 | 重点条目在所属栏目，卡片右上角橙色三角形 | 同时提供无障碍“重点条目”文字；无独立重点栏目 |
| 移动断点 | 约 640 px；标题、卡片内边距相应缩小 | 第一作者单位、长摘要和长链接不得溢出视口 |
| 原文摘要 | 独立左侧竖线区块，`white-space: pre-wrap` | 保留原文换行；不要生成省略号或默认折叠摘要 |

样式源文件是 `site/style.css`。生成的 `site/index.html` 不是手工维护模板；持久的布局变更应改 `scripts/build-site.mjs` 与 CSS，再重新生成。当前页面为静态 HTML，不需要额外前端框架。

HTML 应保留语义层级（页面标题、栏目标题、卡片标题）、正确的中英文 `lang`、可访问的链接文字。外部链接在新标签页打开时使用 `rel="noopener noreferrer"`。若增加图像，必须核查来源、许可、替代文本和移动端尺寸；当前模板以文字为主，没有必需配图。

## 4. 当前 PDF 结构与排版基线

PDF 由同一期 `site/current.json` 生成，采用 **A4 纵向**。左右边距 18 mm、上下边距 22 mm；每页顶端有品牌与刊期，页脚有周报名称和页码。首页保留网页的眉题、中英标题、刊期、条目数、醒目 `AI生成` 告知和统计窗口。浅色页底、栏目左侧色条、**覆盖条目全部内容的白底边框卡片**、浅色摘要面板、标签色块和重点橙色角标与网页呼应；按网页相同栏目及条目顺序排正文。空栏目不显示。

PDF 使用嵌入的中文无衬线常规/粗体字形，不依赖阅读器替换字体；当前优先选择微软雅黑，其次等线或 Noto Sans CJK。可用 `ROBOTICS_NEWS_PDF_FONT_REGULAR` 与 `ROBOTICS_NEWS_PDF_FONT_BOLD` 同时指定字体文件；找不到可嵌入字体时生成失败，先配置字体再重试。中文主标题约 26 pt、栏目标题约 15 pt、条目标题约 13 pt、正文约 9.2 pt，行距大于字号。英文、数字与中文使用同一字族，避免作者姓名和术语因字体替换而出现异常字距。来源链接只显示简短的“来源”或“转载来源”，保持可点击，不铺开长 URL。

PDF 论文条目包含：中英标题、证据及主题标签、日期、来源所示作者姓名（标出第一作者及有依据的通讯作者）、其对应单位或未注明状态、获许可的摘要原文与必要译文或明确的中英转述、可选意义/局限、**一条来源链接**。转载来源需注明。非论文条目包含中英摘要和一条原始来源链接。PDF 也展示最多三个主题；摘要、单位、许可、代码和数据依据链接不另行展示。

论文摘要可能跨页；卡片续页直接接续正文，不重复标签或中英标题，卡片边框与底色应延续，不让正文脱离卡片。摘要用较短的段落作为分页边界，保留原文词句顺序；不要截断原文或在单词中间换页。当前 PDF 使用 ReportLab `Paragraph`，可能规范化原文中的换行和空白；`abstract_original` 数据仍须逐字保存。若某篇摘要的公式、缩进或换行具有实质意义，先确认 PDF 的文本提取结果能保留含义；无法确认时暂缓该条，避免发布失真的摘要。PDF 内部不得出现编辑说明、核查记录、占位符、抓取日志或无效链接。

## 5. 网页和 PDF 的内容一致性

两种输出必须来自同一刊期数据，至少一致于：刊期与统计窗口、入选条目及栏目、标题、证据状态、作者姓名与单位核验状态、论文原文与翻译或转述的明确区分、转载来源标签、非论文中英摘要、意义和局限、来源链接。视觉形式可以不同，但不得在一端删去另一端用于判断可信度的关键限定语。公开 JSON 的条目数和页面条目数应一致。

链接处理：网页的 PDF 按钮应指向当前刊 `diarys/YYYY-MM-DD.pdf` 的可访问 URL；条目唯一的可点击链接取 `primary_url`，优先一手材料，论文经检索仍无一手链接时可指向明确标记的转载页，不指向搜索结果。PDF 中该来源链接应可点击或可辨认。导航用的本期及历史 PDF 链接不计入条目链接数。涉及论文摘要许可时先按 [采编规范](EDITORIAL_GUIDE.md) 核查，不能为了填满模板而复制无权公开的材料。

## 6. 每期内容与结构检查

在[维护手册的发布前检查](WEEKLY_OPERATIONS.md)之外，逐项核对可程序化或文本检查的结果：

- 确认生成命令成功，`site/index.html`、`site/current.json` 和本期 PDF 存在且非空；PDF 可由工具读取页数与基本元数据。
- 对照 `site/current.json` 核对网页中的刊期、统计窗口、条目数、栏目、`AI生成`、证据标签和来源链接；每个 `<article>` 恰有一条指向 `primary_url` 的链接。论文速览也应含可确认的作者姓名、单位核验状态、原文及译文或明确转述。
- 能提取 PDF 文本时，核对刊期、`AI生成`、条目标题、重点标记所在条目、论文第一作者与通讯作者及其单位、摘要及译文；提取工具不能可靠处理某些字体时，记录这一限制。
- 检查 PDF 使用嵌入字体，跨页条目不重复标题，正文仍在卡片内；可选渲染抽查首尾页与跨页样例，留白可随内容自然产生，不为凑页数缩小字体。
- 核查公开 HTML、JSON 和 PDF 中不含内部编辑说明、核查记录或旧版全文贡献总结。
- 同一期重新生成 PDF 前确认是否为修订；旧 PDF 的保留或版本标注需符合[维护手册](WEEKLY_OPERATIONS.md)，不要无说明覆盖已发布内容。

完成内容核验与上述可执行检查后即可进入发布步骤。视觉查看属于可选补充，不应因无法进行而阻断发布；也不要声称已完成未做过的视觉检查。本次任务若已明确授权直接发布，可继续 commit、push 并核验公开站点，否则先交给用户审阅，获得明确同意后再提交。
